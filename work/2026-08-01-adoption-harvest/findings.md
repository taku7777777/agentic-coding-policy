# 4リポジトリ適用からの回収 — 規約側の穴と検証結果

日付: 2026-08-01 / 位置づけ: C(work/。権威なし。第8版候補の素材)

対象: 本日の第7版適用4件(自リポジトリ / metsuke / preference-analyzer / co-working-workflow)の
実施経験を、policy.md 第7版の記載と突き合わせた精査。

## 1. 規約側の穴(実地で判明。すべて実測根拠つき)

### 1-1【最重要】§12.1 の全数列挙が新規導入先で機能しない

§12.1 の列挙手順は「`grep -rl "種別: 記録"` + 追記型運用の文書の目視棚卸し」だが、
**マーカー grep は本日の新規導入3リポジトリすべてで0件**(マーカーは旧規約が配布済みだった
リポジトリにしか存在しない —— 新規先に有るはずがない)。移行対象8本(pref 1 + cww 6 + 自リポ3の内訳は
第6巡に記録済み)は全て**内容判定**で発見した。実際に効いた手がかりは3点:

1. **役割宣言**: README の読む順表・文書自身の位置づけ行(「実測記録」「最新版」等)
2. **git 履歴の不変性**: 初版コミット以来変更0回(= 凍結の実態)
3. **判定質問**: §2 の「時点の記録か」+ §3 の射程フィルタ

「追記型運用の文書」という限定も誤り —— 8本はいずれも追記型ではなく**一度きりの凍結記録**だった。
→ §12.1 を「マーカー grep(旧規約下の検出)+ 内容判定(手がかり3点を明記)」に書き換える。

### 1-2 移行ファイルのヘッダ規定が無く、実施が不整合になった

§12.1 は「ファイル名保持・リンク修正・注記」しか定めておらず、**`日付: / 状態:` 行を欠く
ファイルの扱いが未規定**。結果、本日の実施自体が割れた:

- preference-analyzer の goal.md: ヘッダを**即興で付与**した(日付=初版コミット日)
- co-working-workflow の6本: **無付与のまま**(実測: 6本とも 日付: 行 0)

§6 は「`状態:` 行が有効性を示す唯一の場所」と定めるので、ヘッダ欠落の A は有効性の表示場所を
持たない。→ 規定を追加(「欠くファイルには 日付:(初版コミット日)/ 状態: 行を付す」)し、
cww の6本に**遡及付与**する(回収)。

### 1-3 §12.2 の複製発見 grep から探索パスが脱落(v7 起草時の退行)

v6 §12-2 は `grep -rl "artifact-policy v" ~/.claude/commands ~/.claude/CLAUDE.md ~/.codex/AGENTS.md
~/github/*/AGENTS.md` と探索先を限定していたが、v7 §12.2 は「`grep -rl "artifact-policy v"` で行い」
とだけ書き、**パス集合が消えた**(policy.md:561 実測)。パス無しでは実行不能で、無制限に走らせると
セッションログを拾う(v6 が限定していた理由)。→ パス集合を復元(グローバル2枚も含む形に更新)。

### 1-4 版の発行基準が未定義

§11 の版運用規則は「どこで発行するか」(master 上のみ)を定めるが、**「どの変更が版を要するか」を
定めていない**。本日、§12.3 に「公開リポジトリには per-repo 併置」という**規範的な基準**を
版なしで追加した(9c3244b)—— 運用事実の更新(配布先一覧)と規範の追加が同じ「版なし編集」で
流れた境界事例。→ 「規範の追加・変更は版を上げる / 運用事実(配布先・実施状態)の更新は要さない」を
明文化し、§12.3 の基準は第8版で追認する。

### 1-5 README の導入方法に移行ステップが無い(小)

README の導入方法は3ステップ(コピー / @AGENTS.md / diff 鮮度)のままで、v7 が新設した
**§12.1-2 の1回きり移行**に触れていない。第三者が導入すると容器外 A が未移行のまま残る。
`git show v5:policy.md` の例示も旧タグのまま。→ 1ステップ追記 + 例を v7 に。

## 2. 検証された設計(回収 = 効果の記録)

- **ファイル型容器の廃止が実地で正当化された**: cww の `decision-records.md` は名前は decision log だが
  実体は一度きりの検討記録。v6 の既知名判別(「decision log 等」)なら**名前で誤分類**していた。
  内容と場所で判別する v7 が正しく扱えた
- **本流到達規則の自己適用が2回成立**: metsuke PR #17(到達待ちと記録 → マージ後に完了記録)/
  cww PR #5(即時到達)。「実施済みと書けるのは到達後」が運用として回った
- **グローバル1枚の効果は即日実証**: cww は「未配布なのに work/ 使用24件」の非公式慣行先だった ——
  配布と移行で公式化された。今後の新規リポジトリは配布作業ゼロで規約が効く
- **内容判定の手がかり3点は3リポジトリで再現**(1-1 のとおり)—— 明文化に足る再現性

## 3. 既知のコスト(§10 追記候補)

- **公開リポジトリでのスニペット二重読み込み**: グローバル1枚 + per-repo 併置により、配布済み
  公開リポジトリのセッションではスニペット(66行)が2回コンテキストに載る。内容は同一なので
  矛盾しないが、版更新の過渡期に食い違う窓がある(§12.2 の同時更新で管理)
- **スニペット長は短縮しなかった**: v5 58行 → v7 66行。判別・採番の規則が消えた分を
  射程フィルタ・本流到達等の追加が相殺。段階化(核+本体参照)は将来の検討事項のまま
