### F1【high】版の権威が git ref 間で分裂している — L のマスターが配布コピーより古い

実測(2026-07-30):

- 公開リモートには master(14040cb = **第4版**)しか存在しない(`git ls-remote origin` は refs/heads/master のみ)
- 一方、パイロット先へ配布済みのスニペットは **v5**: `metsuke/AGENTS.md:1`
  `<!-- artifact-policy v5 (2026-07-26) — 本体: agentic-cording-policy/policy.md -->`
- 第5版と、その根拠である第4巡の裁定(`review.md` §10 = **A の記録**)は、未マージ・未プッシュの
  ローカルブランチ `0002-policy-redesign`(worktree `/Users/takuto/tasks/0002-policy-redesign/`)にしか存在しない

これが崩すもの:

1. **§11 の腐り検知が一方向にしか効かない。** `policy.md:377`「本書が改訂されると配布済みのコピーは古くなる」
   —— 想定は「コピーが本体より古い」だけ。現実は**コピー(v5)が本体(master v4)より新しい**。
   スニペットの「本体: agentic-cording-policy/policy.md」を辿ったエージェントは公開 master の第4版を正と読み、
   配布コピーを「壊れた複製」と判定して **v4 へ"修復"しうる**(自信を持って誤る)。逆転を表現する規則も、
   どちらの ref が正かの定義も、policy.md のどこにも無い(「権威ある場所」はパスで定義され、
   同一パスが ref ごとに違う内容を持つ事態を扱えない)
2. **A の不滅性がブランチ運用で破れる。** 第4巡の裁定(A)は `git branch -D` 1回で、§6 のいかなる
   規則にも触れずに消滅する。「A は上書きしない・消さない」は worktree/ブランチの概念を持たない
3. **work/ の同主題追記も ref を跨げない。** ブランチ側に `work/2026-07-26-fourth-review/` が存在するが
   master チェックアウトの `ls -t work/` には映らない。本レビュー自身が §4 に従って同主題ディレクトリを
   探しても発見できなかった(実地で再現)
4. **メタプロセスまで汚染されている。** 本レビューの依頼文自体が「第4版が最新・観測期間〜2026-08-08」
   という master 基準の古い前提で書かれており、第4巡が二重に走った。版分裂は検知されないまま4日経過した

提案: §11/§12 に「配布は master にマージ済みの版からのみ行う」「版番号の発行は master 上の policy.md に限る」
「コピーの版 > 本体の版 を見たら本体の統合を先に行う(コピーを書き換えない)」を明文化。
`0002-policy-redesign` を master へ統合して現状を解消する。

### F2【high】同一パイロット内で計装同士の版が食い違い、修正済みバグが計装経路で再生産される

- `~/.claude/commands/wrap.md:5`「`agentic-cording-policy/policy.md` **第4版**)に従い」
- `~/.claude/commands/wrap.md:12` 形態2 の完了条件「**移動+参照文の両方**」(v4 仕様)
- `metsuke/AGENTS.md:33` 形態2 の完了条件「**「移動」「マーカー」「参照文」のすべて**」(v5 仕様)

§12-4 は昇格の観測を `/wrap` に依存させている(`policy.md:462`)。その `/wrap` が v4 仕様のため、
`/wrap` 経由の形態2 は**マーカー無しで「完了」と判定**される。マーカー欠落はブランチ第4巡-1 が
「昇格直後の A が L 判定になり上書きされる」として修正した当のバグであり、**観測用の計装がそれを再導入する**。

観測期限も3通りに割れている: master `policy.md:461`「〜2026-08-08」(制定日起点)/ ブランチ第5版
「配布日 2026-07-26 起点 → 〜2026-08-09」/ 実際の `metsuke/AGENTS.md` mtime は **2026-07-27 08:16**
(v5 論理なら〜2026-08-10)。監査コマンドの `--since` も 07-25(v4)と 07-26(v5)で食い違い、
実配布日 07-27 とはどちらも合わない。**パイロット終了時、どの監査コマンドを打つべきかが権威ある文書から決定できない。**

根本原因: **版を上げたとき配布済み複製(AGENTS.md 各所+wrap.md)を更新する手順がどこにも定義されていない。**
§12-7 は「展開」を扱うが「更新」を扱わない。wrap.md は §11 の版付け規律(先頭に版を書く)の対象にすら
入っていない —— 版表記が「第4版」と地の文に埋まっており、腐り検知の設計から漏れた3枚目の複製である。

提案: 「版更新時に触るファイルの一覧」(policy.md §11 スニペット・配布先 AGENTS.md 全部・wrap.md)を
§12 に持たせ、wrap.md 先頭にも `artifact-policy vN` 行を義務付ける。

パイロット期間中に発生する横断検討は、故障#5(孤児)の元の条件のまま無防備である。設計順序としては
意図的(パイロットは metsuke に限定)だが、#5 だけ緩和ゼロで走っている非対称は記録しておく。

### F14【low】L 文書冒頭の版履歴パラグラフに成長規則が無い

policy.md は L(上書き)だが、冒頭の「第N版の主な変更」(policy.md:7-11)は版ごとに1段落ずつ積む
A 性の領域で、第5版で既に3段落。上書き文書内のこの領域だけ「消してよいのか・何版分残すのか」が
未定義。L の規則を適用すれば古い版の段落は黙って消せる(消しても §6 違反にならない)が、
review.md の裁定は「変更点は policy.md 冒頭の変更履歴に列挙」(proposal.md:15)へ依存しており、
消すと参照が腐る。ブランチ第4巡の「記録のみ」(規範文と導出メタの混在)に隣接するが、
成長規則の不在は未指摘。

## 4. 総括

設計本体(3分類・昇格2形態・注記方式・work/ の非権威宣言)は第4巡でも正面からは崩れなかった。
崩れたのは今回も外周 —— ただし第3巡(届ける層)よりさらに外の、**時間と並行性の層**である:
版の権威が git ref 間で分裂し(F1)、配布物の更新手順が無く(F2)、修正が計装(F2)にも実地(F3)にも
伝播していない。ポリシーは「複製は腐る」を正しく予言したが、腐ったのは予言と逆方向(本体が複製より古い)
であり、その方向を検知する規則を持っていなかった。パイロットの観測結果を裁定する前に、
F1/F2(どの版が正か・監査コマンドはどれか)の解消が必要である。
