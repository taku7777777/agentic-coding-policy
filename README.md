# agentic-coding-policy

LLMとの作業で生まれる成果物(主に md)の**置き場・権威・寿命**を定める規約。

タスクの途中で生成される成果物(調査結果・レビューFB・下書き・計画など)が散乱し、
どれを信じてよいか分からなくなる問題を解く。既定の置き場を「権威を持たない `work/`」に倒し、
残す価値があるものだけを明示的に昇格させる。

| 読む順 | 文書 | 内容 |
|---|---|---|
| 1 | [issue.md](docs/records/issue.md) | 背景と解決したいこと。当時の記録として凍結 |
| 2 | **[policy.md](policy.md)** | **規約の確定形。これだけで運用できる。現行版は冒頭の版表記を参照** |
| 3 | [proposal.md](docs/records/proposal.md) | 導出の経緯。規約として読まない |
| 4 | [review.md](docs/records/review.md) | 各巡の独立レビューの指摘と裁定。撤回した主張の記録 |

(当時形の記録3本は第7版で `docs/records/` へ移動した —— 規約自身の §8 に従った配置。policy.md §2.1)

## 導入方法

1. [policy.md](policy.md) §11 のスニペットを、対象リポジトリの **`AGENTS.md`** にコピーする
2. 同じリポジトリの `CLAUDE.md` に `@AGENTS.md` の1行を置く
   (Codex は `AGENTS.md` を、Claude Code は `CLAUDE.md` 経由で同じ内容を読む)
3. 配ったコピーが古いかどうかは、**コピーの本文と policy.md §11 のブロックを `diff` して**確かめる。
   スニペット先頭の版ヘッダ(`<!-- artifact-policy vN … -->`)はスニペットの内容が最後に変わった版を
   指し、本体の版とは独立に動くので、番号が違うこと自体は古さを意味しない
   (番号で分かるのは「コピーが本体より新しい」という異常のほうだけ。policy.md §11)

`git tag`(`v3` 以降)が各版のツリーを指す。`git show v5:policy.md` で配布時点の本体を復元できる。

`work/` 配下は本ポリシー自身の作業過程であり、権威を持たない(policy.md §2)。

手元のリポジトリ8本を実測して導出している。うち非公開の個人リポジトリ2本は
`priv-A` / `priv-B` と匿名化し、内容が特定できるファイル名・引用は `<…>` で伏せた。
